# Deploying the October 2026 update
# 2026年10月更新 — 部署步驟

This puts the new `deliverables/Code.gs` live. Do it **after** PR #2 is merged.

- **Staff page (`index.html`)** goes live as soon as the PR is merged, because GitHub Pages serves `main`. It works with both the old and the new backend, so staff can keep using it the whole time.
- **Backend (`Code.gs`)** changes only when you paste it into Apps Script and deploy a new version (step C). Until then the old backend keeps running.

Budget about 30 minutes. Steps A–B use a copy of the Sheet, so nothing live is touched until step C.

You will need two values that are **not** in this repo (keep it that way):
- `TEST_CODE`: any made-up access code for the copy, e.g. `test1234`. Never use the real code.
- `TEST_URL`: the copy's own web-app link, which you create in B2.

---

## A. Make a copy of the Sheet for a test run

1. Open the live timesheet Google Sheet.
2. **File → Make a copy**.
3. Name: `Timesheet TEST copy (delete after)`. **Untick** "Share it with the same people". Click **Make a copy**. The copy opens in a new tab. Do everything in A–B in **that tab**.
4. In the copy: **Extensions → Apps Script**. The copy's own script project opens (still the old code).
5. Left sidebar: **⚙️ Project Settings** → scroll to **Script Properties**:
   - If `NOTION_API_KEY` is listed, click **Edit script properties**, delete that row and save. **The copy must not write to the real Notion HR database.** The Notion part is covered by the offline tests.
   - Set `ACCESS_CODE` to your `TEST_CODE` (add it if it isn't there).
6. Left sidebar: **⏰ Triggers**. A copy normally has none. If any are listed, delete them in the copy.

## B. Paste the new Code.gs into the copy and run the 7-step test

**B1. Paste.** In the copy's Apps Script editor, click `Code.gs` in the file list, select all (Cmd+A), delete, then paste the whole of `deliverables/Code.gs` from `main`. Click **💾 Save**. There should be no red error bar.

**B2. Give the copy its own test link.** **Deploy → New deployment** → ⚙️ next to "Select type" → **Web app**. Description `TEST copy`, Execute as **Me**, Who has access **Anyone** → **Deploy** → authorise if asked → copy the **Web app URL**. That is your `TEST_URL`. It only reaches the copy.

Now run the 7 steps. Each one says what you should see.

1. **Health page is plain text (A1).** Open `TEST_URL` in a browser. ✅ It shows only the line `Timesheet API is running. 工作紀錄系統運作中。` as plain text, not a styled page.

2. **Submit, with tricky text (I1).** In Terminal, paste the command below after replacing `TEST_URL` and `TEST_CODE`:
   ```bash
   curl -L "TEST_URL" -H "Content-Type: text/plain" -d '{"action":"submit","accessCode":"TEST_CODE","entries":[{"staffName":"Test User","phoneNumber":"91230000","dateOfWork":"2026-10-01","workVenue":"+WOW Mall","basicRate":800,"startTime":"10:00","endTime":"18:00","pic":"Michael","notes":"=1+1","entryId":"deploytest-0001"},{"staffName":"Test User","phoneNumber":"91230000","dateOfWork":"2026-10-01","workVenue":"Test Hall","basicRate":600,"startTime":"19:00","endTime":"22:00","pic":"Michael","notes":"-30 min break","entryId":"deploytest-0002"}]}'
   ```
   ✅ Reply: `{"status":"success","rowsAdded":2,"duplicates":[2],"alreadySaved":[]}`.
   ✅ In the copy's `Timesheet_Submissions`, two new rows. Column E shows `+WOW Mall` and column I shows `=1+1` and `-30 min break ⚠️ Possible duplicate 可能重複` **as text**: no `2`, no `#ERROR!`. Column N is `Pending`, and column M has the Final Rate formula.

3. **A retry never duplicates (D2).** Run **the exact same command again**. ✅ Reply: `"rowsAdded":0` … `"alreadySaved":[1,2]`. ✅ No new rows appear in the sheet.

4. **Status still works.**
   ```bash
   curl -L "TEST_URL" -H "Content-Type: text/plain" -d '{"action":"status","accessCode":"TEST_CODE","phoneNumber":"91230000"}'
   ```
   ✅ Two submissions, venues `+WOW Mall` and `Test Hall`, times `10:00`/`18:00` and `19:00`/`22:00`, status `Pending`.

5. **Dashboard (P3, P4, L5).** Reload the copy's Sheet tab. **Timesheet ⏱ → Show Pending**.
   ✅ The new last column is **Notes 備註**. The `Test Hall` row is **red** (possible duplicate), and the alert says 1 row is a possible duplicate.
   On the **+WOW Mall** row only: type Project No. `0123`, pick Role `Event Helper`, tick ✓ → **Timesheet ⏱ → ✓ Approve Checked**.
   ✅ In `Timesheet_Submissions`, that row's column J shows `0123` (leading zero kept) and column N shows `Approved`.

6. **FPS list, payment lists and Mark as Paid (P1, P2, P5, round 2 #1).** **Timesheet ⏱ → Refresh Payroll** → tick `2026-10` → Confirm. When it asks **Sync to Notion?**, click **NO**.
   ✅ `Staff_Directory`: the FPS list column D is headed **TO PAY 待支付** and shows **$800** for Test User. (Pretend accounting paid this $800 list.)
   Now approve the `Test Hall` row as well (Show Pending → fill Project No. `0123` + Role → tick → Approve). Run **Refresh Payroll** again (tick `2026-10`, answer **NO** to Notion).
   ✅ TO PAY now shows **$1,400**: this is a second, separate payment list.
   **Timesheet ⏱ → 💰 Mark Approved as Paid**.
   ✅ A window lists **two** payment lists, newest first: `2026-10 · 2 job(s) · HK$1,400` (marked *newest 最新*) and `2026-10 · 1 job(s) · HK$800`. Both may show the same minute; tell them apart by the total.
   Nothing is pre-selected (on purpose). Pick the **HK$800** list (the one "paid") → **Next**.
   ✅ The confirm box starts `Payment list … 1 job(s), HK$800`, says **1 job, total HK$800** will be marked Paid, and says **1 other approved job (HK$600) is not on this list and stays Approved**. Click **YES**.
   ✅ `+WOW Mall` becomes `Paid`. `Test Hall` stays `Approved`.
   Open **Mark Approved as Paid** once more. ✅ Only one list is left: `1 job(s) · HK$600`. Click **Cancel**.

   **Sync to Notion menu (round 2).** **Timesheet ⏱ → 🔄 Sync to Notion** → tick **Select all** → Confirm.
   ✅ Because the copy has no Notion key, it reports `Notion sync finished: 0 synced, 0 warning(s), 1 error(s)`, and `Sync_Log` shows `NOTION_API_KEY not set`. That is expected and proves the copy can't reach Notion.

7. **Clean up the copy.** In the copy's Apps Script: **Deploy → Manage deployments** → select `TEST copy` → **Archive**. Then delete the copy (Google Drive → right-click → **Move to trash**).

If any ✅ doesn't match, stop here. Don't touch the live script; send your assistant a screenshot of what you saw.

## C. Paste into the LIVE script and publish a new version (same URL)

1. Go back to the **live** Sheet → **Extensions → Apps Script**.
2. Optional safety net: select all the old code, copy it, and paste it into a note named `Code.gs backup 2026-10`.
3. Click `Code.gs` → select all → delete → paste all of `deliverables/Code.gs` from `main` → **💾 Save**.
4. Check **⚙️ Project Settings → Script Properties**. `ACCESS_CODE` and `NOTION_API_KEY` should still be there; pasting code doesn't change them.
5. **Deploy → Manage deployments**.
6. Select the existing **Web app** deployment (the one staff use), then click the **✏️ pencil (Edit)** icon.
7. **Version** dropdown → **New version**. Description: `Oct 2026 health-check fixes`.
8. Click **Deploy**, then **Done**. **Do not** use "New deployment": that creates a different URL and the staff page would keep calling the old one.
9. Check: open your usual live web-app link. ✅ It now shows the plain text line (step B, test 1). Then submit one real-looking test entry from the staff page on your phone, check it appears, and delete that row.

## D. Run Refresh Payroll once

Back in the live Sheet: **reload the tab**, then **Timesheet ⏱ → Refresh Payroll** → tick the month(s) you haven't paid yet → Confirm. Answer the Notion question as you normally would.

Why: every Refresh Payroll now saves its TO PAY jobs as a separate **payment list**. **Mark Approved as Paid** asks which list accounting paid (newest first, with HK$ total and job count) and marks only that list's jobs. The very first time, there is no list yet, so it will ask you to refresh first.

From now on:
- Accounting should say **which list (time + HK$ total)** they paid from. Pick that one in Mark as Paid.
- A Notion sync that stopped at the time limit is finished with **Timesheet ⏱ → 🔄 Sync to Notion**, not by refreshing payroll again.
- Paid lists disappear. Unpaid lists disappear after 45 days; refresh again if one expires.

## E. Check that no trigger, menu or button points at a renamed function

Internal functions were renamed with a trailing `_`, which makes them private. A web page can no longer call them (finding A1). A **trigger** or **button** that used an old name would now fail with "Script function not found".

1. Live Apps Script → left sidebar **⏰ Triggers**. For each trigger, read the **Function** column. If it shows any name from the **Old name** column below, delete that trigger. A private function can't be a trigger target. Every one of these is already run from the menu. For example, the Notion sync runs from Refresh Payroll or **🔄 Sync to Notion**. Don't point a trigger at `syncToNotion` either: it opens a window, which a trigger can't show. Tell your assistant what the trigger did.
2. In the Sheet, look for drawings or images used as buttons. Right-click → ⋮ → **Assign script**. If one shows an old name, clear it.
3. Reload the Sheet and open the **Timesheet ⏱** menu. It now has **6** items: the same 5, plus **🔄 Sync to Notion 同步到Notion** at the bottom.
   - Names that did **not** change: `onOpen`, `doGet`, `doPost`, `showPendingDashboard`, `approveSelected`, `rejectSelected`, `refreshPayroll`, `markApprovedAsPaid`, `runPayrollForMonths`.
   - **New** public names: `syncToNotion` (menu item), `runSyncForMonths` (its month window), `runMarkPaidBatch` (the payment-list window).
   - **Removed:** `runMarkPaidForMonths`, replaced by `runMarkPaidBatch`. If a Mark-as-Paid window was left open in a browser tab from before the update, close it and open the menu again.

## Read-only checks L1–L11 (on the live Sheet / Apps Script / Notion; change nothing)

These come from the health check (section 3). Several are now handled in code, but existing data may still need a look.

- [ ] **L1 Back door closed.** After step C, open the live web-app link: plain text only, no page. (Before step C, the old page was the hole.)
- [ ] **L2 Old `+`/`-` text.** Filter `Timesheet_Submissions` columns B, E and I for `#ERROR!` / `#NAME?`. New rows are safe now; fix any old ones by retyping them with a leading `'`.
- [ ] **L3 Column M health.** Filter column M for blanks / `#VALUE!` on Approved rows. Payroll now falls back to F + L or flags ⚠️ CHECK. Fix any flagged row (usually text typed into OT column L).
- [ ] **L4 Time zone.** File → Settings → Time zone is still `(GMT+08:00) Hong Kong`.
- [ ] **L5 Project No.** Look in column J for numbers that lost a leading zero (`123` for `0123`) or became dates. New approvals keep the text, but old values need retyping.
- [ ] **L6 Notion Crew phones.** The sync now also finds `+852 …`, `9123-4567` and `9123 4567` forms. Look for any **duplicate Crew pages** made before this fix and merge them by hand.
- [ ] **L7 Notion size.** Any crew member near 100 Jobs Assigned, or `ERROR … 2000` rows in `Sync_Log`? Those rows will sync on the next run. Over 100 links shows a WARNING to add by hand.
- [ ] **L8 Two rows, one person.** The next time someone has 2+ new rows in one sync, check in Notion that their Crew page got both links and both Work Log lines (the code now remembers the Crew page within a run).
- [ ] **L9 Highlights.** Format → Conditional formatting on `Timesheet_Submissions`: note any manual red/yellow rule. The Dashboard now shades duplicates red by itself.
- [ ] **L10 Deployed version.** Deploy → Manage deployments: the web app shows the version you made in step C, with today's date.
- [ ] **L11 `ACCESS_CODE` set.** Project Settings → Script Properties lists `ACCESS_CODE`. If it's missing, the server accepts any code.
